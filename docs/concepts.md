# Domain Concepts and Terminology

This document establishes the authoritative vocabulary model for SWE_SEED. Per specification [0012](specs/0012-existing-harness-reconciliation.md), where historical or invented terms conflict with proven BAML schemas and CLI definitions, the proven vocabulary documented here is authoritative.

---

## 1. Governance & Capability Concepts

### RouteCard
- **What it is**: A structured JSON definition residing under `.agent-harness/routes/<id>.json` representing one of 11 required job types. It declares the task purpose, semantic triggers, positive/negative examples, required context files, required active skills, ordered work loop, required artifacts, pre-bound proof commands, and explicit done conditions.
- **What it is NOT**: It is not a prompt template, not a conversation persona, and not a soft recommendation. It is a machine-readable specification of task obligations.
- **Related concepts**: Work Contract, Semantic Router, ContextPack.
- **Implementation**: `crates/swe-seed-core/src/route/mod.rs` (`RouteCard`), `.agent-harness/baml/baml_src/harness.baml`.

### Work Contract
- **What it is**: The pre-execution agreement produced by `swe-seed route "<task>"`. It binds the selected RouteCard, assembled ContextPack, required artifacts, proof commands, and initial trace genesis before code modification begins.
- **What it is NOT**: It is not an informal summary, not a post-execution diff report, and not subject to modification during execution.
- **Related concepts**: RouteCard, Proof Gate, Trace Genesis.
- **Implementation**: `crates/swe-seed-core/src/route/mod.rs` (`RouteDecision`), `crates/swe-seed/src/cli.rs`.

### SeedPackageManifest
- **What it is**: The top-level capability inventory for the repository, located under `.swe-seed/manifest.toml`. It catalogs all registered `LayerCapability` entries, their owner layers, artifact paths, review status, and cryptographic hashes.
- **What it is NOT**: It is not a package manager lockfile (like `Cargo.lock` or `pnpm-lock.yaml`) and not an installable package archive.
- **Related concepts**: LayerCapability, SweSeed Layer, BoundaryReport.
- **Implementation**: `crates/swe-seed-core/src/seed/manifest.rs` (`SeedPackageManifest`), `.agent-harness/baml/baml_src/swe_seed.baml`.

### LayerCapability
- **What it is**: A discrete governed capability (skill, rule, hook, command, or agent) registered in the SeedPackageManifest, explicitly tagged with its owner layer (`SweSeed`, `Harness`, or `Fabricator`), source specification, and artifact metadata.
- **What it is NOT**: It is not an arbitrary source code file or helper function. Only governance-relevant units are LayerCapabilities.
- **Related concepts**: SeedPackageManifest, BoundaryReport, ArtifactMetadata.
- **Implementation**: `crates/swe-seed-core/src/seed/capability.rs` (`LayerCapability`), `.agent-harness/baml/baml_src/swe_seed.baml`.

### BoundaryReport
- **What it is**: A deterministic audit artifact generated by `swe-seed seed validate-boundaries` evaluating cross-layer integrity. If any capability violates downward ownership or misses required parent artifacts, it records `BoundaryFinding` entries and sets `passed = false`.
- **What it is NOT**: It is not a code linter report and not a test runner output. It validates architectural layer discipline.
- **Related concepts**: SweSeed Layer, LayerBoundaryGovernance.
- **Implementation**: `crates/swe-seed-core/src/seed/boundary.rs` (`BoundaryReport`, `BoundaryFinding`).

## 2. Execution, Context & Trace Concepts

### Bounded Context & ContextPack
- **What it is**: The explicit collection of files and documents assembled by `swe-seed context-plan "<task>"` for a specific route. It provides the minimal necessary context needed to execute the work loop while enforcing token and size budgets.
- **What it is NOT**: It is not an entire repository dump, not a vector similarity search result, and not an open-ended search index.
- **Related concepts**: ContextBudget, RouteCard, Token Containment.
- **Implementation**: `crates/swe-seed-core/src/context/pack.rs` (`ContextPack`), `crates/swe-seed-core/src/context/budget.rs` (`ContextBudget`).

### ContextBudget
- **What it is**: The policy rules defined in `.agent-harness/context/budget-policy.yaml` governing tool output containment, raw output size caps, and session continuity. It prevents agents from exhausting context windows with raw logs.
- **What it is NOT**: It is not an API token billing or cost tracking budget. It is an in-context volume constraint.
- **Related concepts**: ContextPack, Tool Output Containment.
- **Implementation**: `crates/swe-seed-core/src/context/policy.rs` (`BudgetPolicy`).

### Trace & TraceSchema
- **What it is**: A durable JSON record stored under `.agent-harness/traces/records/<trace-id>.json` capturing the complete lifecycle of a task: task description, route decision, timestamped events, stage checkpoints, completion claims, and proof execution results.
- **What it is NOT**: It is not an unstructured conversation transcript, not an LLM chat history, and not an ephemeral log file.
- **Related concepts**: Trace Ledger, Routing Gate, ProofRecord.
- **Implementation**: `crates/swe-seed-core/src/trace/lifecycle.rs`, `crates/swe-seed-core/src/trace/record.rs` (`TraceRecord`), `.agent-harness/baml/baml_src/harness.baml`.

### Trace Ledger & Genesis
- **What it is**: An append-only SQLite database located at `.agent-harness/traces/ledger.db` that maintains a cryptographically verifiable SHA-256 hash chain of all route decisions and trace transitions. Every valid trace begins with an immutable `RouteSelected` genesis entry.
- **What it is NOT**: It is not a distributed blockchain, not a central telemetry server, and not a git commit history.
- **Related concepts**: Trace, Routing Gate (`route_gate`).
- **Implementation**: `crates/swe-seed-core/src/trace_ledger.rs` (`TraceLedger`, `verify_chain`).

### Routing Gate
- **What it is**: The verification mechanism implemented in `swe-seed gate <trace-id> --verify`. It computes and validates the SHA-256 hash chain in the trace ledger and confirms that the trace originated from a genuine `RouteSelected` genesis event. If unrouted or tampered with, it exits non-zero, blocking CI merges via `just gate-merge`.
- **What it is NOT**: It is not a branch protection rule in GitHub and not a code review approval. It is a cryptographic pre-condition for mergeability.
- **Related concepts**: Trace Ledger, RouteSelected Genesis.
- **Implementation**: `crates/swe-seed-core/src/routing_gate.rs` (`route_gate`, `RouteGate`).

## 3. Verification & Evaluation Concepts

### ProofRecord & ProofDisposition
- **What it is**: A structured proof claim linking an agent's completion assertion to concrete executed commands, timestamps, exit codes, and stdout/stderr evidence. A claim without an exit code of 0 has `disposition = Rejected`.
- **What it is NOT**: It is not a prose summary or a promise that "all tests pass". It requires recorded command output.
- **Related concepts**: Proof Gate, EvalResult.
- **Implementation**: `crates/swe-seed-core/src/eval/proof.rs` (`ProofRecord`, `ProofDisposition`).

### EvalSpec, EvalCheck & EvalResult
- **What it is**: The deterministic test specification system used by `swe-seed eval run --spec <path>`. An `EvalSpec` defines required `EvalCheck` items (static file assertions, command executions, boundary verifications). Once a run begins, the `EvalSpec` is frozen; editing the spec to make a failing run pass is strictly prohibited.
- **What it is NOT**: It is not an LLM-graded eval or non-deterministic prompt benchmark. Every check is a deterministic command or structural assertion.
- **Related concepts**: ProofRecord, Doctor.
- **Implementation**: `crates/swe-seed-core/src/eval/spec.rs`, `crates/swe-seed-core/src/eval/check.rs`, `crates/swe-seed-core/src/eval/result.rs`.

## 4. Multi-Host Projection & Hooks

### HostAdapter & Projection
- **What it is**: Adapters in `crates/swe-seed-core/src/adapters/` that translate canonical harness rules, skills, and hooks into host-native tool files (for Claude, Codex, OpenCode, GitHub Copilot, Antigravity, and CI). `swe-seed sync --host <host>` generates these projections.
- **What it is NOT**: It is not an agent emulator or custom IDE. It is a configuration compiler targeting host files.
- **Related concepts**: Managed Block, Drift Detection, Snapshot Rollback.
- **Implementation**: `crates/swe-seed-core/src/adapters/host.rs` (`HostAdapter`), `crates/swe-seed-core/src/adapters/projection.rs`.

### Managed Block
- **What it is**: Specific delimited comment markers (`<!-- BEGIN SWE_SEED MANAGED BLOCK -->` and `<!-- END SWE_SEED MANAGED BLOCK -->`) embedded in projected files. Only text between these markers is overwritten during `sync`. User customizations outside the markers are preserved.
- **What it is NOT**: It is not a proprietary file format. It uses standard comment syntax for Markdown, YAML, and JSON.
- **Related concepts**: HostAdapter, Drift Detection.
- **Implementation**: `crates/swe-seed-core/src/adapters/marker.rs`.

### HookRuntime & HookPolicy
- **What it is**: The lifecycle interception runtime managed by `swe-seed agent-hooks`. It receives agent events (`UserPrompt`, `PreToolUse`, `PostToolUse`, `TurnEnd`), applies redaction to prevent secret leakage, checks permissions against `HookPolicy`, logs to `.agent-hooks/events.jsonl`, and indexes into SQLite.
- **What it is NOT**: It is not an operating system sandbox and not an authorization daemon.
- **Related concepts**: PermissionPolicy, Redaction.
- **Implementation**: `crates/swe-seed-core/src/hooks/runtime.rs`, `crates/swe-seed-core/src/hooks/policy.rs`.

## 5. Learning & Continuous Adaptation

### LearningRecord & SkillProposal
- **What it is**: Artifacts produced by reflecting upon completed traces (`swe-seed reflect <trace-id>`). A `LearningRecord` extracts lessons, failure patterns, or reusable procedures. If viable, it is promoted via `swe-seed learn` into a `SkillProposal` or a `RegressionCase`.
- **What it is NOT**: It is not autonomous, unreviewed self-modification. Promotion requires explicit human review and must include a documented rollback plan.
- **Related concepts**: ReflectionTemplate, RegressionCase, AdaptationDecision.
- **Implementation**: `crates/swe-seed-core/src/learning/mod.rs`, `crates/swe-seed-core/src/learning/proposal.rs`.

## 6. Prototyping & Semantic Chain

### Fabricator Semantic Specification Chain
- **What it is**: The 10-node traceable specification chain defined in `FABRICATOR_SPEC_v0.1.0.md`:
  `ProductSeed -> JobStory -> ProductHypothesis -> PRD -> ProductADR -> EARSRequirements -> SDS/Components -> GherkinScenarios -> TDDPlan -> AgentTask -> FabricatorEvalSpec -> FabricatorProofRecord`.
  Each artifact references its immediate predecessor via a `TraceabilityLink`.
- **What it is NOT**: It is not a free-form chat session. It is a formal semantic chain where missing links cause chain validation to fail.
- **Related concepts**: Fabricator Layer, SemanticChainValidationReport.
- **Implementation**: `crates/swe-seed-core/src/fabricator/artifacts.rs`, `crates/swe-seed-core/src/fabricator/chain.rs`.

## 7. Gateway & Federation

### MCPGate (MCP Gateway)
- **What it is**: The tool-plane proxy specified in [0020](specs/0020-mcpgate.md). It discovers local and remote Model Context Protocol (MCP) servers, namespaces tool names (`<server>.<tool>`), enforces permission policies, redacts arguments/results, and proxies JSON-RPC 2.0 requests over stdio and SSE transports.
- **What it is NOT**: It is not an LLM chat gateway and not an API router for model providers. It exclusively manages MCP tool connections.
- **Related concepts**: HookRuntime, PermissionPolicy.
- **Implementation**: `crates/swe-seed-core/src/gateway/mod.rs`, `crates/swe-seed-core/src/gateway/serve.rs`.

### Federation & SemanticEventEnvelope
- **What it is**: The optional integration plane specified in [0011](specs/0011-sea-loop-federation.md). It allows SWE_SEED to emit signed event envelopes to external SEA-Loop systems (SEA-Forge, Context Kernel, GodSpeed-Agent). Private keys are Ed25519 and encrypted at rest with SOPS.
- **What it is NOT**: It is not a mandatory dependency. If federation is toggled off (`--federation off`), the core harness runs 100% locally and self-contained.
- **Related concepts**: Trace, SOPS Key Management.
- **Implementation**: `crates/swe-seed-core/src/federation/mod.rs`, `crates/swe-seed-core/src/federation/signing.rs`.
