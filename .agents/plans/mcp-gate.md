# MCPGate SWE_SEED Delta Plan

Status: scratch implementation plan, revised 2026-07-02.

Reader and action: this plan is for the engineer implementing the remaining MCPGate runtime
inside SWE_SEED. Use it to build only the delta that specs `0006` and `0020` require, while
preserving the existing registry, harness, federation, context, and Fabricator boundaries.

Normative source: `docs/specs/0020-mcpgate.md` is the source of truth for the target
contract. This file is an execution plan, not a spec.

## Reviewed Baseline

The earlier standalone MCP Gateway draft overlapped with SWE_SEED and included product
scope that does not fit this codebase. The project already has:

- Capability registry concepts in `docs/specs/0003-capability-registry.md`.
- Host adapter projection and MCP config generation in `docs/specs/0004-host-adapter-contract.md`.
- Hook and PermissionPolicy enforcement in `docs/specs/0005-normalized-hook-runtime.md` and
  `crates/swe-seed-core/src/hooks/policy.rs`.
- Base MCP gateway contract in `docs/specs/0006-mcp-gateway-integration.md`.
- Scan and provenance gates in specs `0007` and `0009`.
- Optional SEA federation envelope boundary in `docs/specs/0011-sea-loop-federation.md` and
  `crates/swe-seed-core/src/federation/`.
- Local context budgeting in `docs/specs/0015-context-budget-plane.md`.
- Fabricator semantic-chain proof artifacts in `docs/specs/0017-fabricator-layer.md`.
- A Rust CLI binary in `crates/swe-seed/src/cli.rs`, but no gateway command family yet.

The useful delta is therefore not a universal standalone gateway. It is a Rust gateway
runtime embedded in the existing `swe-seed` binary and driven by SWE_SEED's existing
registry, policies, proof records, and federation flags.

## Scope To Implement

Implement the parts of MCPGate that SWE_SEED does not yet have:

1. `swe_seed_core::gateway` runtime models and validation:
   - `GatewayBackend`, derived from registered `MCPServer` entries.
   - `GatewayCatalogEntry`, derived from backend tools/resources/prompts.
   - `GatewaySession`, generated by the runtime, never supplied by clients.
   - `GatewayGovernanceState`, with atomic session, client, and tool counters.
   - typed gateway errors matching spec `0020`.
2. Compact MCP discovery and namespaced invocation:
   - preserve the spec `0006` meta-tools: `swe_seed_list_servers`,
     `swe_seed_list_tools`, `swe_seed_search_tools`, and `swe_seed_invoke`.
   - route namespaced calls only to their owning backend.
   - never fail over a stateful namespaced tool call to a different backend.
3. Request completion evidence:
   - every request returns either a backend response or typed gateway error.
   - every allow, deny, backend failure, hash mismatch, and governance block writes a local
     audit record before the request is complete.
   - audit uses hook redaction rules and never stores raw credentials.
4. Permission and integrity gates:
   - use existing `PermissionPolicy` semantics.
   - enforce approval gates before forwarding.
   - enforce scan and provenance status where policy requires it.
   - verify pinned catalog definition hashes at call time.
5. Session and budget enforcement:
   - check and increment counters in one critical section.
   - persist counter deltas before forwarding through a small local journal or equivalent
     replayable file-first mechanism.
   - replay before accepting traffic after restart.
6. Backend health and resilience:
   - support `stdio` and HTTP first, with SSE and WebSocket only after the base proof passes.
   - maintain per-backend health and circuit breaker state.
   - bound retries and concurrency.
   - expose health and metrics for operator inspection.
7. Validated reload:
   - compile runtime snapshots from the registry, policy, and `.swe-seed/` gateway config.
   - apply valid snapshots only to future requests.
   - keep the last-known-good snapshot on invalid reload.
8. OpenAPI import:
   - import OpenAPI operations into registry-backed gateway catalog entries.
   - record source hash and provenance metadata.
   - make re-import idempotent.
9. Federation projection:
   - when federation is off, construct no SEA envelopes and make no external calls.
   - when federation is on, use only `swe_seed_core::federation`.
   - map gateway route, authority, context, proof, and settlement events as specified in
     `docs/specs/0020-mcpgate.md`.
   - local audit records must cite emitted or consumed envelope ids or record suppressed
     dispatch.
10. Fabricator evidence links:
    - allow gateway audit/proof refs to appear in `FabricatorProofRecord`.
    - do not mutate Fabricator semantic-chain artifacts during request routing.

## Explicit Non-Scope

Do not implement these parts of the standalone draft:

- No separate `~/.mcp-gateway/skills.json` registry. Use `SeedPackageManifest`, `SkillIR`,
  `MCPServer`, `LayerCapability`, and `ArtifactMetadata`.
- No standalone setup wizard that owns host configs. Use existing host adapters and managed
  regions.
- No Docker requirement. The deliverable is the Rust `swe-seed` binary.
- No default public bind. Bind to `127.0.0.1` by default. Non-loopback requires explicit
  tunnel mode or TLS policy.
- No independent authentication server, API-key authority, key server, or mTLS product
  unless a later SWE_SEED spec narrows that need. Local host use is the default.
- No LLM or chat-completions gateway.
- No custom federation protocol, message bus, direct Context Kernel/SEA-Forge/GodSpeed side
  channel, or settlement store.
- No separate context plane. Use `ContextBudget`, `ContextPack`, and optional context
  federation through spec `0011`.
- No default skill exposure as MCP tools. Imported skills stay governed by SkillIR; if they
  expose tools, those tools enter the same gateway path.
- No EE-derived firewall, transparency-log, message-signing, cost-accounting, or
  tool-integrity modules. Implement only project-native scan, provenance, redaction,
  PermissionPolicy, audit, and pinned-hash checks.

## Binary And Daemon Direction

The target is a lightweight, cross-platform Rust daemon mode inside the same `swe-seed`
binary:

```text
swe-seed gateway serve
swe-seed gateway doctor
swe-seed gateway import mcp <path-or-host>
swe-seed gateway import openapi <path-or-url>
swe-seed gateway list
swe-seed gateway proof --routing
swe-seed gateway proof --concurrency 64
swe-seed gateway proof --reload
```

Implementation notes:

- Add a `Gateway` command family to `crates/swe-seed/src/cli.rs`.
- Add `crates/swe-seed/src/gateway_cli.rs` as CLI glue.
- Add `crates/swe-seed-core/src/gateway/` for runtime, catalog, MCP protocol, governance,
  audit, health, reload, and import code.
- Keep optional heavy dependencies out until a proof requires them. Prefer the existing Rust
  workspace dependencies and file-first state.
- A release build should produce one useful executable. Distribution may later package
  config/templates, but the runtime should not require Docker or a sidecar service.

## Staged Implementation

### Stage 1: Gateway Module Skeleton And Typed Errors

Create the module and CLI shape without forwarding traffic yet.

Deliverables:

- `swe_seed_core::gateway::{GatewayError, GatewayResult}`.
- model structs for `GatewayBackend`, `GatewayCatalogEntry`, `GatewaySession`, and
  `GatewayGovernanceState`.
- CLI stubs for `gateway doctor`, `gateway list`, and `gateway proof`.
- tests proving model serialization, typed error mapping, and CLI help stability.

Proof:

```text
cargo test -q -p swe-seed-core gateway
cargo test -q -p swe-seed --test cli_golden
just harness-validate
```

### Stage 2: Registry-Derived Catalog And Compact Discovery

Build catalog snapshots from the registry or manifest. Do not introduce a second source of
truth.

Deliverables:

- deterministic namespace validation.
- compact list/search APIs with schema-size caps.
- dropped or filtered entries recorded deterministically.
- proof that full backend schemas are not dumped into routed context.

Proof:

```text
cargo test -q -p swe-seed-core gateway_catalog
cargo run -q -p swe-seed -- gateway list
```

### Stage 3: Permission, Approval, Scan, And Hash Gates

Wire invocation decisions through existing policy surfaces before backend forwarding exists.

Deliverables:

- `swe_seed_invoke` dry-run path returning allow, approval-required, or typed denial.
- PermissionPolicy deny-overrides-allow behavior reused from hooks policy.
- scan/provenance-required blocks.
- call-time `pinned_hash` verification.

Proof:

```text
cargo test -q -p swe-seed-core permission_gate gateway_policy
```

### Stage 4: Local Audit And Request Outcome Contract

Add local gateway audit records and make audit write part of request completion.

Deliverables:

- redacted JSONL audit writer under `.swe-seed/gateway/audit/` or another documented
  project-local state path.
- one audit record for every allow, deny, backend-unavailable, invalid request, hash
  mismatch, session block, and budget block.
- failure to write audit returns a typed internal error and does not silently complete.

Proof:

```text
cargo test -q -p swe-seed-core gateway_audit
```

### Stage 5: Stdio And HTTP Backend Routing

Implement the minimal router for registered stdio and HTTP MCP backends.

Deliverables:

- JSON-RPC request id preservation.
- `tools/list`, `tools/call`, `resources/list`, `resources/read`, `prompts/list`, and
  `prompts/get` as the initial method set.
- bounded timeouts and malformed-response handling.
- namespaced calls never reroute to another backend.

Proof:

```text
cargo test -q -p swe-seed-core gateway_routing
cargo run -q -p swe-seed -- gateway proof --routing
```

### Stage 6: Session Sandbox And Atomic Governance

Add runtime sessions and replayable governance counters.

Deliverables:

- server-generated session ids with at least 128 bits of entropy.
- max call and max duration enforcement.
- per-session, per-client, and per-tool counters.
- critical-section updates with durable counter deltas before forwarding.
- crash/restart replay test.
- concurrent edge test proving counters do not overrun.

Proof:

```text
cargo test -q -p swe-seed-core gateway_governance
cargo run -q -p swe-seed -- gateway proof --concurrency 64
```

### Stage 7: Health, Breakers, Metrics, And Reload

Add operator visibility and safe runtime config changes.

Deliverables:

- per-backend `healthy`, `degraded`, and `down` state.
- breaker `closed`, `open`, and `half_open` state.
- request count, latency, backend health, breaker, active session, and governance metrics.
- validated snapshot reload with last-known-good rollback.

Proof:

```text
cargo test -q -p swe-seed-core gateway_health gateway_reload
cargo run -q -p swe-seed -- gateway proof --reload
```

### Stage 8: OpenAPI Import

Import REST/OpenAPI operations into SWE_SEED's registry-backed gateway catalog.

Deliverables:

- deterministic operation naming from `operationId`.
- input schema from parameters and request bodies.
- source hash and ArtifactMetadata provenance.
- idempotent re-import with no semantic diff for unchanged documents.

Proof:

```text
cargo test -q -p swe-seed-core gateway_openapi_import provenance_verify
```

### Stage 9: Federation Projection

Add online envelope projection only after local request handling is proven.

Deliverables:

- no envelope construction, dispatch, consume, or wait when `federation.enabled=false`.
- `RouteSelected`, `AuthorityChecked`, `ContextRequired`, `ContextPacketCreated`,
  `ProofStarted`, `ProofCompleted`, and `SettlementRecorded` integration only through
  `swe_seed_core::federation`.
- local audit records cite envelope ids or suppressed-dispatch disposition.
- incoming envelopes rejected on `domain_model_hash` mismatch before affecting routing,
  authority, context, proof, or settlement.

Proof:

```text
cargo test -q -p swe-seed-core federation_parity federation_signing gateway_federation
cargo test -q -p swe-seed-core standalone_invariant
```

### Stage 10: Fabricator Evidence Links

Connect gateway proof and audit evidence to Fabricator artifacts without making Fabricator a
runtime dependency of request routing.

Deliverables:

- gateway proof refs can be cited by `FabricatorProofRecord`.
- chain validation still gates Fabricator handoff.
- gateway request routing cannot mutate Fabricator chain artifacts.

Proof:

```text
cargo test -q -p swe-seed-core fabricator gateway_fabricator_evidence
```

## Acceptance Criteria

Implementation is complete only when:

- gateway runtime reads from the SWE_SEED registry or manifest and has no competing registry.
- compact discovery, namespaced routing, PermissionPolicy, approval, scan, provenance, and
  hash gates operate before forwarding.
- every request completes with response-or-typed-error plus local audit.
- federation-disabled mode proves zero external calls.
- federation-enabled mode records required semantic-envelope disposition through
  `swe_seed_core::federation`.
- session and budget counters remain correct under concurrent calls.
- backend health and breaker state prevent unbounded retries.
- reload preserves last-known-good snapshots.
- OpenAPI import is idempotent and provenance-backed.
- Fabricator integration is evidence-only and keeps semantic-chain validation intact.
- the gateway runs as part of the Rust `swe-seed` binary without Docker.
